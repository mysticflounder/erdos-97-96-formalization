# Exact ingress and consumer contract

## Scope

The carrier is exactly the 17 slots `0..16`.  The case matrix is the Cartesian
product of two source orientations, two deleted-Q choices, and two retained-row
choices, for eight tags.  The query is a finite support abstraction, not a
Euclidean coordinate model and not a universal ingress theorem.

## Structural ingress

V5 imports all corrected v2 assertions from
`freshthird_five_survivor_alias_aware_v2/run_query.py` and then adds the v3
row-center omissions and exact-center alias constraints.  It retains the v4
public endpoint/Q consequences:

```text
C3 in Cap; C4 in Cap
C3 != Q0; C3 != Q1; C4 != Q0; C4 != Q1
```

Their Lean source map is pinned through v4 `SOURCE-MAP.md`.  In particular,
there is no invented center/support injectivity.  Each SAT model is checked
again in Python against the v2 invariants, v4 cuts, row-center omissions,
four-element supports, and exact-center alias support equality.  Missing
values, diagonal distance nodes, malformed supports, and incomplete cut
provenance fail closed.

## Equality-path consumer

For each of the nine named rows, membership of `u` and `v` in a row centered at
`c` source-entitles

```text
dist(c,u) = dist(c,v).
```

The runner represents the physical distance as the unordered edge `{c,u}` and
builds the equality graph generated by all row-support pairs.  Aliases are
therefore handled physically, not by symbolic label.

Only these five rows have source-entitled offsupport exactness:

```text
PRow, PRhoRow, S0Row, S1Row, DBRow.
```

For one of these exact rows at `c`, equality closure from a supported edge
`{c,u}` to an excluded carrier edge `{c,x}` contradicts exact support.  This is
the finite combinatorial shadow of `CriticalFourShell.support_eq_radius` plus
exact support/off-radius transport (including the general blocker exactness
interface `GeneralCarrierBridge.exactAt_blocker`).  V5 does **not** use a
nonmember of `R`, `Rh`, `B3`, or `B4` as a distance disequality.

The recorded path is a shortest simple path in the assignment's equality
graph.  Its learned clause is exactly the negation of the conjunction of:

- every row-center role equality used by the path;
- the two row-support memberships used by each path edge;
- the exact row's center equality, supported endpoint membership, and excluded
  endpoint nonmembership.

Duplicate facts are merged.  The verifier reconstructs the path and rejects
every omit-one version of the source-fact list.  “Weakest” here means precisely
the path-fact conjunction, not a claim that the clause is a globally prime
implicate of the full v2 formula.

## CEGAR endpoint and certificate scope

The structural solver is lazy: it is not constrained to v4's chosen models.
Every conflicting assignment produces one checked cut, after which the solver
may choose any remaining support/role assignment.  A tag stops at either:

1. the same accumulated query is UNSAT in z3 and cvc5; or
2. z3 and cvc5 each return a structurally valid equality-clean survivor.

The present wave reached endpoint 2 for all tags.  The evidence consists of
dual solver replay, exact SMT2 inputs, parsed model snapshots, an independent
union-find equality checker, and source-path validation.  It is not a DRAT/LRAT
proof certificate and does not provide exhaustive geometric or universal
coverage.

## Controls

Both solvers replay:

- a known SAT equality model;
- a member-to-offmember equality cycle, UNSAT;
- three omit-one variants, each SAT;
- a non-exact-row equality chain with no fabricated offsupport disequality,
  SAT.

## Explicit nonclaims

No artifact here proves a P97 counterexample, a Euclidean realization, a
universal-cardinality lift, a Lean theorem, or closure of a production `sorry`.
