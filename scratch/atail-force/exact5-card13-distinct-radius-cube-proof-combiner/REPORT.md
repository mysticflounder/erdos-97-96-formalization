# Exact-five card-13 distinct-radius cube-proof combiner

## Critical source-to-CNF correction

The two existing 64-cube covers are covers of CNFs emitted by
`exact5-card13-distinct-radius-aggregate/export_cnf.py` through the external
Z3 tactic pipeline

```text
simplify; propagate-values; elim-term-ite; solve-eqs; lia2card; card2bv;
bit-blast; tseitin-cnf
```

There is no Lean theorem, verified compiler trace, or generated source-ingress
theorem connecting the live/source hypotheses to those two Z3 CNFs.  Their
root hashes are therefore not eligible endpoints for closing a Lean `sorry`:

- direct: `1669221a2e8791256c92038be8577e85ea1dc3204d0acfa106b064460a5dcff8`;
- mirror: `347a6a6bcd207be3d142734c118366d91644cd056da27abac88fd7fb0bbd63cf`.

Even a complete set of kernel-checked LRAT leaf proofs would establish only
UNSAT of those external CNFs.  Until the Z3 source transformation itself is
proved sound against the Lean source predicate, those covers are usable for
core discovery and solver profiling, not publication closure.

The corrected route is generated by
`generate_verified_distinct_aggregate_bvexpr.py`.  It rebuilds the same
ordered 58,433 source expressions and defines the root CNF in Lean as

```lean
AIG.toCNF sourceExpr.bitblast.relabelNat
```

The compiler and source-expression-to-CNF equisatisfiability theorem are then
inside Lean's verified `BVLogicalExpr` stack.  A final production ingress must
still prove that the actual source hypotheses make `sourceExpr.eval` true,
analogously to the existing pass-5 source ingress.

## Scope

This isolated scratch lane supplies only the generic Lean combination step for
a future distinct-radius `march_cu` certificate.  It does not run a cuber,
change piqd, generate the final certificate, or touch production/shared docs.

## Lean contract

The implementation uses `Std.Sat.CNF`, the same semantic `CNF.Unsat` target
returned by `Std.Tactic.BVDecide.Reflect.verifyCert_correct`.

- `Cube.Literals alpha` is a list of signed `Std.Sat.Literal alpha` values.
- `Cube.unitClauses` turns every cube literal into a singleton CNF clause.
- `Cube.withCube root cube = root ++ Cube.unitClauses cube`.
- `Cube.Exhaustive cubes` says every total assignment satisfies at least one
  listed cube.
- `Cube.blockingCNF cubes` contains one clause formed by negating each cube;
  `Cube.exhaustive_of_blockingCNF_unsat` turns a checked UNSAT proof for this
  CNF into the required exhaustiveness certificate.
- `unsat_of_exhaustive_cubes` proves `root.Unsat` from exhaustiveness and a
  proof that every listed `root ++ units(cube)` is UNSAT.
- `CNF.Unsat.of_clause_subset` transports an UNSAT proof for a kept clause
  subset to the full augmented cube CNF.

`CubeProofBundle.root_unsat` is the generated-coordinator entrypoint.

The preferred route is now:

1. generate the one root CNF as
   `AIG.toCNF sourceExpr.bitblast.relabelNat` inside Lean;
2. cube and certify that exact root CNF, allowing arbitrary internal
   AIG/Tseitin variables;
3. combine coverage and leaves with `CubeProofBundle.root_unsat`; and
4. apply `BVLogicalExpr.unsat_of_compiledCnf_unsat` to lift the compiled-root
   result back to `sourceExpr.Unsat` using `AIG.toCNF_equisat`,
   `AIG.Entrypoint.relabelNat_unsat_iff`, and
   `BVLogicalExpr.unsat_of_bitblast`.

No root-to-source variable alignment is needed after the whole exact compiled
root CNF is proved UNSAT.  What matters is that the cuber consumes the bytes
emitted from that Lean definition, rather than the unrelated Z3 CNF.

`BVLogicalExprCubeProofCombiner.lean` supplies a fallback portable boundary.
Its cubes are conjunctions of signed source-level
`BVLogicalExpr`s.  From an exhaustive source cube list and an UNSAT theorem for
every independently compiled expression

```lean
.gate .and sourceExpr (SourceCube.expr cube)
```

it proves `sourceExpr.Unsat`.  The root and leaf AIG/Tseitin auxiliary
variables may be completely different.  Thus this combiner does not require,
and intentionally does not state, that a leaf CNF equals the root CNF plus
unit clauses.

`SourceCube.fullTruthTable` recursively enumerates both polarities of an
ordered source-expression list.  The checked theorems
`length_fullTruthTable` and `exhaustive_fullTruthTable` show that nine source
expressions produce exactly 512 cubes with structural coverage, avoiding 512
manual cases or a separate blocking-CNF certificate.

## Source assertion-core endpoint

Compiling the entire 58,433-assertion root is not logically necessary if the
solver can extract small UNSAT cores for each source-expression cube.  The
source-level combiner now contains the generic checked bridge:

```lean
SourceAssertions.unsat_source_and_cube_of_core_unsat
```

If every expression in `core` is implied by `source`, then UNSAT of

```text
sourceCube ∧ conjunction(core)
```

implies UNSAT of the exact leaf expected by the portable cube combiner,

```text
source ∧ sourceCube.
```

The implication is semantic and does not depend on CNF variable identity.
Each small leaf can therefore be bit-blasted independently and LRAT-checked
through Lean's verified `BVLogicalExpr` compiler.

The kernel-cheap representation of an extracted original assertion index is a
pair of bounded indices:

```lean
SourceAssertions.ChunkedIndex sourceAssertionChunks
```

Its fields are a chunk index and an offset into that chunk.  With the current
64-assertion chunking, original zero-based assertion `i` maps to
`(i / 64, i % 64)`.  The mapping should be regenerated from the same ordered
assertion stream and pinned by orientation plus source-expression SHA-256; it
must not be recovered from Z3 CNF clause or auxiliary-variable numbers.

`eval_getChunked_eq_true_of_chunkedConjunction_eq_true` proves that a true
two-level source conjunction makes the selected original assertion true.  It
performs two bounded `List.get` projections: one through the 914-entry outer
chunk list and one through a list of at most 64 assertions.  A generated core
adapter defines only a list of `ChunkedIndex` values;
`chunkedConjunction_impliesCore` maps those indices to expressions and proves
the whole `ImpliesCore` contract generically.  No per-core proof branches are
needed.  This avoids elaborating or reducing membership in a flattened
58,433-expression list.

This endpoint is fail-closed even if an external core index is mapped
incorrectly: Lean proves implication for the expressions actually selected,
and the independently compiled core certificate must still prove those exact
expressions UNSAT.  A bad mapping can prevent closure but cannot prove a false
theorem.

The split generator exposes the source as the same two-level assertion list;
the leaf generator emits selected `(chunk, offset)` values for the checked
cores and feeds their per-cube theorems toward
`unsat_of_exhaustive_source_cubes`.

### Reduced-union correction

The final source endpoint should not require evaluation of all 58,433 source
assertions.  For each orientation, take the ordered union of the original
source assertion indices occurring in its 512 final checked leaf cores.  Every
leaf core is a subset of that union, so:

1. UNSAT of `fullSourceCube ∧ leafCore` transfers to
   `reducedUnion ∧ fullSourceCube`;
2. the structurally exhaustive 512-cube truth table proves
   `reducedUnion.Unsat`; and
3. the source-ingress callback needs to prove only the selected union
   assertions.

`SourceAssertions.conjunction_impliesCore_get` is the checked generic subset
lemma.  It consumes only positions in the reduced-union list and proves the
`ImpliesCore` contract required by the existing leaf-core transport.

The complete unminimized best-core manifests currently generate:

- direct: 512/512 checked leaves, 146,165 total leaf-core entries, maximum
  leaf core 5,094, and a reduced union of 17,537 source assertions;
- mirror: 512/512 checked leaves, 150,724 total leaf-core entries, maximum
  leaf core 5,277, and a reduced union of 18,043 source assertions.

`generate_verified_source_core_leaves.py` accepts these oversized cores
without a minimization threshold.  It emits one `ReducedUnion` root, 512
independent exact leaf expressions, and for each leaf the offsets proving that
its original source-index core is a subset of the union.  Optional later core
minimization may replace expensive leaves and shrink the union, but is not a
prerequisite for certification.

The full 58,433-assertion root CNF hashes remain valuable encoding audits and
fallback whole-root targets.  They are not the intended final ingress surface.

## Dispatcher-facing endpoint shape

`ExactFiveCard13DistinctRadiusDispatcher.lean` expects direct and mirror
callbacks generic in `{M N P star T}`.  The certificate modules should export
fixed source theorems of the form

```lean
directSourceUnsat : BVLogicalExpr.Unsat VerifiedDistinctDirect.sourceExpr
mirrorSourceUnsat : BVLogicalExpr.Unsat VerifiedDistinctMirror.sourceExpr
```

The source-ingress layer, not the certificate combiner, should then export two
thin theorems with arguments matching the dispatcher fields verbatim:

```lean
∀ {M N P star T}, (C : CanonicalCoverFamilies T) →
  P.sourceIndex = 1 ∧ P.blockerIndex = 2 ∧ P.thirdIndex = 3 → False

∀ {M N P star T}, (C : CanonicalCoverFamilies T) →
  P.sourceIndex = 3 ∧ P.blockerIndex = 2 ∧ P.thirdIndex = 1 → False
```

Each ingress theorem constructs the corresponding fixed BV assignment from
the generic semantic table and cover-family packet, proves `sourceExpr.eval`
is true, and applies the fixed UNSAT theorem.  This lets the final closers be
assigned directly to `CanonicalDistinctRadiusCard13OrbitClosers.direct` and
`.mirror`, without specializing or repackaging the generic source objects.

## Instantiating from an original-CNF `march_cu` manifest

This section describes a sound raw-CNF proof when the root CNF itself is the
trusted theorem target.  It does **not** bridge the current Z3-generated
distinct-radius CNFs back to the P97 source hypotheses.

For a raw-DIMACS piqd job with original header `p cnf N M`, the generated Lean
coordinator must perform the following fail-closed steps.

1. Parse the job's original CNF blob, whose hash is recorded on the job, into
   one pinned `root : Std.Sat.CNF Nat`.  DIMACS variable `k` maps to the
   zero-based natural `k - 1`; positive literals map to `(variable, true)` and
   negative literals to `(variable, false)`.  This is the same variable type
   and polarity convention used by piqd's current LRAT Lean endpoint, so no
   unchecked `Nat`/`Fin N` relabeling is needed.
2. Fetch the manifest's `cubes_icnf` blob and verify its recorded SHA-256.
   Parse every nonempty `a ... 0` assumption line in order into
   `cubes : List (Cube.Literals Nat)`.  Check that the parsed list length and
   each literal list agree exactly with the manifest's ordered `CubeEntry`
   records (`idx`, `lits`).  No cube may be dropped or reordered silently.
3. Build `Cube.blockingCNF cubes`, whose clause for cube `C` is the disjunction
   of the negations of all literals in `C`.  Kernel-check an LRAT proof that
   this blocking CNF is UNSAT and apply
   `Cube.exhaustive_of_blockingCNF_unsat`.  This is the fail-closed coverage
   certificate: the per-cube LRAT proofs and the march_cu manifest alone do not
   prove that the cubes cover every assignment.
4. For each manifest entry, fetch and hash-check its `kept_cnf` and `lrat`
   blobs.  The existing piqd LRAT emitter yields
   `keptCnf.Unsat` via `verifyCert_correct`.
5. Prove, by checked computation over the parsed clauses, that every clause of
   `keptCnf` occurs in `Cube.withCube root cube`.  Apply
   `CNF.Unsat.of_clause_subset` to obtain the exact per-cube theorem required
   by `CubeProofBundle.cubeUnsat`.  This subset step is necessary because
   `drat-trim`/piqd compaction may retain only the original clauses used by the
   proof.
6. Assemble the exhaustive theorem and all ordered per-cube theorems into
   `CubeProofBundle root cubes`; `CubeProofBundle.root_unsat` is then the final
   root-CNF UNSAT theorem.

The proof manifest currently stores `cubes_icnf` and per-cube `idx`, `lits`,
`kept_cnf`, and `lrat` blobs.  The original root-CNF identity comes from the
owning piqd job, not from `ProofManifest` itself, so the coordinator must pin
both the job's original CNF hash and the proof-manifest hash.
