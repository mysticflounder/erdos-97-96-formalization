# P97 generic exact midpoint/equal-radius planar screen

Date: 2026-09-05
Scope: exact n=12 counterexample mining. This is not a Lean formalization result and does not close radius-ten cell 16.

## Result

A label-generic C++20 screen now subsumes the fresh cell-16 planar certificate. Given a 12-center support table (partial rows allowed as zero masks), it:

1. forms the exact equivalence quotient of the 66 unordered distance variables generated by selected-row equalities;
2. enumerates all equal-sided simple four-cycles on four distinct labels;
3. adds each rhombus affine identity `e_a-e_b+e_c-e_d=0` to an exact rational row span;
4. tests every midpoint target `2e_m-e_a-e_b` for membership in that span;
5. if such a midpoint is forced and the quotient also gives `d(a,m)=d(a,b)` or `d(b,m)=d(b,a)`, returns an exact no-distinct-planar-realization conflict.

The contradiction is generic: if `m=(a+b)/2` and `d(a,m)=d(a,b)` with `a!=b`, then `d(a,m)=d(a,b)/2`, impossible. No convex-order hypothesis is used.

## Validation

Compiled with:

```
g++ -std=c++20 -O3 -Wall -Wextra -Wpedantic -Werror
```

The fresh cell-16 support table is rejected with midpoint triple `(0,6,7)`, anchor `0`, 8 detected rhombi, and affine rank 8.

A known exact planar 4x3 square-grid nearest-neighbor fixture is not rejected (6 rhombi, rank 6). Empty/partial data is unresolved rather than promoted to UNSAT.

All 16 previously certified seven-row cell-16 cuts are rejected when only those seven rows are supplied; the other five rows are zero/unassigned. Thus the generic screen subsumes every literal learned cut in `p97-cell16-2026-09-05/results/learned-row-cuts.json`.

Relabeling stress: 1,000 deterministic random permutations of the cell-16 table were all rejected.

Throughput stress: 10,000 deterministic arbitrary n=12 four-support tables were screened in 1.88928 seconds in this runtime (~5293 tables/second), with 9,491 midpoint conflicts. These arbitrary tables are a speed/robustness diagnostic, not a valid P97 search census.
