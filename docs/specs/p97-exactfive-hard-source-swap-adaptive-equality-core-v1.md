# P97 exact-five hard source-swap adaptive equality core v1

Status: implementation specification. No Singular target result is authenticated
by this document.

## Purpose and boundary

This lane asks one PIQD-managed Singular engine whether the ideal generated by
the 13 squared-distance row equalities of survivor profile 1697 is the unit
ideal over `QQ`. It tests the same order-independent equality set under the two
affine gauges supplied by the completed adaptive order/NRA run. The fresh
orders select only the points pinned to `(0,0)` and `(1,0)`; they are not two
independent order witnesses for this algebraic query.

`UNIT` is one-engine discovery evidence for the fixed equality ideal. `NONUNIT`
does not establish a real point. No result establishes source realization,
source elimination, a mathematical theorem, a Lean statement or proof, or
promotion.

## Equality construction

For each fresh gauge, the producer reconstructs the current adaptive planar
system from the current frozen sources. It requires exactly 11 quotient point
classes and the rows `T0`, `K1`, `K2`, and `L` in that order. The row supports
have sizes 5, 4, 4, and 4. Each row uses its first support as pivot and emits
one squared-distance difference against every remaining support, yielding
`4 + 3 + 3 + 3 = 13` polynomials.

The canonical template uses class IDs and all 22 symbolic coordinates. It is
constructed without consulting either total order, and both target contexts
must carry the same ordered template and template hash. Only afterward does a
target substitute rank zero by `(0,0)` and rank one by `(1,0)`. The remaining
nine points contribute exactly 18 `QQ` ring variables, ordered by the canonical
class records and then by `x,y`. The ordered substituted polynomials, their
canonical JSON hash, exact variable list, and exact Singular script hash are
bound in the source context.

The script is rendered only by
`census/global_confinement/equality_ideal_probe.py:singular_script`. It declares
a characteristic-zero `dp` ring, computes `slimgb`, and reduces `1`. The result
is read only through that module's begin/end marker protocol and
`parse_singular_verdict`.

## Mandatory controls

The following controls execute sequentially before either target:

1. `<z,z-1>` must return `UNIT`;
2. `<z^2-1>` must return `NONUNIT`;
3. `<x^2+y^2,x^2+y^2-1>` must return `UNIT`;
4. `<x^2+y^2-1>` must return `NONUNIT`.

Each control uses the same marker script renderer, PIQD Singular runner,
custody validation, timeout, transcript checks, and deterministic UUID request
identity as the targets. A mismatch aborts and no terminal is written.

## PIQD execution and validation

All six queries use one freshly constructed `PiqdSingularRunner`, one worker,
and sequential execution. The timeout is an integer in `1..86400` seconds and
defaults to 900. There is no local backend and no fallback. Request IDs are
canonical UUIDv5 strings derived from a fixed namespace and the SHA-256 of the
canonical source context.

Every newly returned execution is immediately replayed with
`validate_artifact_directory`, and every returned custody field must match the
local replay. Existing per-query directories are never overwritten; they are
validated locally. Validation checks the exact current script and source
context, request identity, project, timeout, source path, run status, exit code,
stream hashes, empty stderr, untruncated streams, strict UTF-8 stdout, and an
exact three-line nonempty marker transcript. Singular diagnostics, extra stdout,
malformed or duplicate markers, bad process status, nonzero exit, partial
artifacts, and custody tampering are never accepted as `UNIT` or `NONUNIT`.

## Statuses

The immutable terminal status is one of:

- `BOTH_GAUGES_UNIT`;
- `BOTH_GAUGES_NONUNIT`;
- `GAUGE_DISAGREEMENT`; or
- `TARGET_INCONCLUSIVE`.

The first three require two parsed target verdicts. A timeout, process failure,
diagnostic, or malformed target transcript yields `TARGET_INCONCLUSIVE` after
custody validation. Control failures abort without a terminal. A unit-ideal
status remains one-engine discovery only.
