# Profile 0034 physical assertion deletion v1

This lane searches within the authenticated common 48-assertion formula from
the completed profile-0034 physical block deletion run. It is a bounded
discovery campaign. It does not establish a source theorem, source coverage,
minimality, Lean ingress, or promotion.

## Frozen input

The producer authenticates the predecessor run manifest, launch, terminal,
both selected result trees, and the execution-critical source modules. The LT
and GT selected journals must match byte for byte. Their retained group list is
fixed to four supporting-edge groups and four source-row equality groups. The
common journal must reconstruct as 44 supporting-edge assertions followed by
four row assertions, for 48 assertions total.

Each assertion receives a source-order ID `assertion-000` through
`assertion-047`. Its descriptor binds the parent group, source entry, command,
position, and command hash. Candidate journals keep the declaration preamble
and physically omit selected assertion commands. They contain no Boolean
guard, implication, named atom, or solver assumption.

## Search

Two small QF_NRA transport controls run in order before the search. Each
control has its own exact verifier and does not replay the predecessor chain.

The search begins with the 48-assertion parent formula and its authenticated
UNSAT result. It partitions the current assertion IDs into stable near-equal
blocks, starting at granularity two. Every candidate from one round is based on
one unchanged current list and may run concurrently. A shared executor permits
at most 20 queries. If several candidates return custody-valid UNSAT, only the
first candidate in canonical block order is accepted. Other results remain
diagnostics and their deletions are never combined. After an accepted deletion,
the producer restarts partitioning from the new current list.

When block refinement reaches assertion-sized blocks, the producer runs a
singleton pass. Any accepted singleton deletion starts a fresh singleton pass
from the new current list. SAT, rejected SAT replay, UNKNOWN, malformed output,
and transport loss retain the assertion. The target-query cap is 160. A cap or
an inconclusive final singleton batch leaves deletion stability false.

## Solver custody

Every query uses Z3 through PIQD at a fixed 60,000 ms deadline. It creates one
fresh named session, appends one complete physical journal, performs one solve,
collects the receipt and exported journal, and closes the session. Request IDs
bind the lane, run, query key, current digest, and deleted-block digest. Partial
launches do not resume. A completed run replays only against its recorded
execution commit.

SAT readback is accepted only after exact rational checking of the fixed frame
and every retained supporting-edge or row assertion. Unsupported algebraic
readback is unresolved. UNSAT is discovery evidence about the authenticated
formula only. UNKNOWN remains unresolved.
